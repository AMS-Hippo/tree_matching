# Documentation notebooks

Syntax-oriented notebooks live here. They are meant to be read and run from the repository root, but each notebook also has a small bootstrap cell for running from this folder against the `src/` layout.

Current notebooks:
- `SYNTAX_basic_matching.ipynb`
- `SYNTAX_partial_beam_matching.ipynb`
- `SYNTAX_embedding_clustering.ipynb`
- `SYNTAX_subgraph_matching.ipynb`
- `SYNTAX_template_repeat_matching.ipynb`
- `SYNTAX_neural_exemplar_extraction.ipynb`
- `UNITTEST_exact_matcher_dev.ipynb`


`SYNTAX_basic_matching.ipynb` and `SYNTAX_partial_beam_matching.ipynb` document `method="beam"` as a partial-matching beam search over valid matched prefixes, not the older row-wise sparse-DP approximation.

`SYNTAX_partial_beam_matching.ipynb` also shows the optional `beam_lookahead=True` mode, which precomputes capped discounted descendant-label sketches plus fixed-length downward path-chunk sketches and uses their overlap as a non-admissible far-lookahead ranking feature.

Sparse exact matching is available in two forms:

- `TreePathMatcher(method="sparse_chain")` uses bucketable weights and the exact
  product-poset chain algorithm.  Its default candidate configuration is exhaustive
  with respect to the blocking keys.
- `FastSparseTreePathMatcher(mode="equality" | "overlap")` is the specialized
  integerized version for the same score families supported by `FastTreePathMatcher`.
  For many comparisons, call `fit_encoder(all_trees)` before preparing any
  tree, prepare every tree once with `prepare_tree(...)`, and use
  `predict_prepared(...)`. Unseen labels are dropped with an explicit warning,
  and prepared sparse trees cannot be mixed across incompatible encoder fits.

`FastBeamTreePathMatcher(mode="equality" | "overlap")` is the prepared,
encoded score-only implementation of the partial-matching beam.  It reuses one
corpus-wide encoder and per-tree token-posting indices.  Equality mode matches
the generic `beam_partial_score` candidate semantics; overlap mode uses a
direct shared-token posting expansion.  See [`FAST_BEAM.md`](FAST_BEAM.md).

The older `TreePathMatcher(method="sparse")` remains available as the sparse-cell
skip-closure DP so that the two implementations can be benchmarked separately.
If preprocessed sparse trees are scored later with a different bucketable
weight, matching is allowed to continue but emits a warning: the result may be
exact only relative to the candidates generated by the original blocking keys.

Opt-in timing and work counters for the dense, beam, sparse, and specialized
fast matchers are documented in [`DIAGNOSTICS.md`](DIAGNOSTICS.md). Construct a
high-level matcher with `collect_diagnostics=True` and inspect
`last_diagnostics_` after `predict(...)`.

The reproducible dense/sparse/beam benchmark harness is documented in
[`PATH_MATCH_BENCHMARKS.md`](PATH_MATCH_BENCHMARKS.md). It includes named
algorithm presets, controlled `TreeData`-native synthetic regimes, and a CLI
that writes row-level diagnostics and summary CSV files.

The cumulative implementation state, first standard-preset observations, and
remaining algorithmic work are summarized in
[`PATH_MATCH_STATUS.md`](PATH_MATCH_STATUS.md).

The notebook-facing pairwise ranking benchmark is
[`../benchmarking/01_algorithm_ranking.ipynb`](../benchmarking/01_algorithm_ranking.ipynb).
It keeps the smoke/standard controls small, applies the exact-oracle and coverage
gates, and displays timing and percent-of-optimum accuracy separately.

The repeated query-to-template benchmark is
[`../benchmarking/02_throughput.ipynb`](../benchmarking/02_throughput.ipynb).
It fits shared encoders once, prepares every tree once where the API permits,
validates prepared calls against direct calls, and separates setup time from
warm score-matrix throughput.
